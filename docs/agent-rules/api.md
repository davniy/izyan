# API и интерфейсы

- CLI — публичная поверхность: субкоманды `analyze`, `scan`, `eval`,
  `remediate`, `knowledge`; новые флаги — с разумными дефолтами и документацией в
  usage; обратная совместимость флагов не ломается без причины.
- `report.json` / `case.json` — персистентные схемы: новые поля
  `omitempty`, существующие не переименовываются (рестарт кейса читает
  старые файлы).
- Экспорты и отчёты: человекочитаемые `report.md` (RU) и `report.en.md`
  (EN) — tracker-ready документ с девятью обязательными разделами в
  фиксированном порядке: `## Результат`, `## В чём уязвимость`,
  `## Почему она применима / не применима к этому продукту`,
  `## Что подтверждено`, `## Что не удалось подтвердить`,
  `## Оценка и приоритет`, `## Рекомендация по исправлению`,
  `## Использование AI`, `## Ссылка на технический аудит`. Технические
  детали (claims с evidence IDs, реестр доказательств, data flows,
  журнал инструментов, полные limitations) — в отдельных
  `report.audit.md` / `report.audit.en.md`; `report.json` остаётся
  машинным источником — новые поля (`severity_source`, `score_source`,
  `triage_disposition`, `base_priority`) добавляются аддитивно с
  `omitempty`. OpenVEX, CycloneDX, tracker_comment — строгая валидация
  против схемы формата, не «почти VEX».
- Входные контракты generic: `--vuln-file` (OSV JSON), `--ticket`
  (generic tracker JSON), корпуса `eval/corpus-real.json` и
  `eval/live-corpus.json` — env-экспансия в путях, относительные
  пути резолвятся от файла корпуса.
- Ошибки CLI — понятные сообщения и корректный exit code; usage на
  stderr при неверных флагах.
