# Протокол независимой разметки корпуса (B29)

Цель — разорвать замкнутый контур «автор инструмента разметил
ground truth и сам его оценил». Второй аннотатор проверяет
signal-cleared кейсы вслепую и фиксирует, сколько снятий он
подтверждает, не видя вердиктов анализатора.

## 1. Подготовка материалов

```bash
# материализовать продукты и сгенерировать audit packets
izyan eval --corpus eval/corpus-real.json --audit-dir eval/audit
```

Рецензенту передаются:

- каталоги продуктов `eval/.gen/<case-id>` (или repo-путь кейса);
- advisory кейса (`eval/advisories/…` либо `vuln_file` из corpus);
- **не передаются**: вердикты, `expect`, `eval/report`, `case.json` —
  разметка должна быть слепой.

## 2. Вопрос разметки

Для каждого кейса аннотатор отвечает на один вопрос:

> Достижим ли дефектный локус advisory attacker-controlled входом
> в этом снапшоте продукта?

Допустимые ответы: `exploitable` / `not exploitable` /
`cannot determine (нужна доп. информация — указать какая)`.

Фиксируется: ответ, затраченные минуты, ключевое наблюдение
(1–2 строки: «payload — const», «пакет вне `go list -deps`»).

## 3. Сверка

После завершения слепого прохода:

1. Открыть audit packets `eval/audit/<case-id>.md` — там вердикт,
   grounding falsifier и рецепт проверки.
2. Для каждого расхождения: повторить рецепт из пакета
   (`govulncheck` baseline, `go list -deps`, просмотр site-файлов)
   и записать, кто ошибся и почему.
3. Согласие засчитывается только если аннотатор может назвать тот
   же класс доказательства (или лучший), что в пакете.

## 4. Метрики

- **доля подтверждённых снятий** — согласие на cleared-кейсах;
- **экспертная стоимость** — медиана минут на кейс (экономика
  триажа: цена проверки ≈ цене ручного разбора, а не ниже —
  тогда audit packet не удешевляет процесс);
- **расхождения по классам** — на каких falsifier'ах ревьюер не
  согласен (сигнал для углубления negative verification именно
  этого класса).

## 5. Правила

- Аннотатор не пользуется `izyan` и `case.json` до фиксации ответа.
- `INCONCLUSIVE` от аннотатора — валидный ответ; он означает, что
  доказательства в пакете недостаточно для человека тоже.
- Кейсы с `expert_assisted` размечаются отдельной строкой:
  согласие там проверяет основание эксперта, не автономность
  инструмента.
